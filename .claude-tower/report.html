ブランチissue-259-de002832-subtask-1

2. 実装結果

成功

Claude実行を最大実行時間付きで実行するようにした。
上限超過時、実装ジョブはneeds_attention、アイデア出しジョブはfailedで終了し、ワーカーは解放される。

3. 変更内容

No.ファイル変更
1core/config.pyjob_max_runtime_seconds（7200）、idea_job_max_runtime_seconds（1800）を追加。
2worker/time_limit.py（新規）run_with_time_limit：asyncio.run(asyncio.wait_for(...))で実行し、超過時はClaudeTimeoutErrorを送出。
3worker/main.py_run_claude_for_jobをrun_with_time_limit経由に変更。
process_jobでClaudeTimeoutErrorを捕捉し、errorイベント記録＋needs_attentionで終了。
4worker/idea_runner.py_executeをrun_with_time_limit経由に変更。
超過時は既存の例外処理でfailed＋エラーメッセージを記録。
5tests/test_worker_time_limit.py（新規）ほか打ち切り・キャンセル、実装ジョブのneeds_attention遷移、アイデア出しジョブのfailed遷移、設定既定値のテストを追加。

コミット: b465129（設定と共通関数）、2e5414e（実装ジョブ）、e61c38a（アイデア出しジョブ）

4. 自律判断した事項

No.判断理由・前提
1既定値は実装ジョブ2時間、アイデア出し30分。実装ジョブは大きなタスクで長時間かかり得るため、誤打ち切りを避ける余裕を持たせた。
アイデア出しは読み取り専用の調査のみのため短めにした。
いずれも.envで変更可能。
2打ち切り処理をworker/time_limit.pyに共通化した。実装ジョブとアイデア出しジョブで同じ処理になるため。
worker/main.pyがidea_runnerをimportしており、どちらかに置くと依存が逆転するため。
3専用例外ClaudeTimeoutErrorを設けた。他の失敗（failed）・利用上限（rate_limited）と区別して状態を決めるため。
4実装ジョブのイベント種別はerrorとした。既存のエラー表示やcore/idea_context.pyのエラー集計にそのまま乗せるため。
5アイデア出しジョブはイベント記録を行わず、エラーメッセージとログのみ残す。アイデア出しジョブには実行イベントの仕組みが無いため。

6. 残課題・リスク・レビュー観点

  • 打ち切り時、Claude Agent SDKの非同期ジェネレータはキャンセルされるが、Claude CLIの子プロセスが確実に終了するかは実機未確認。
  • 打ち切った実装ジョブはセッションIDを保存しないため、再実行時は前回より古いセッションから再開される。
  • 上限超過のneeds_attentionはworktreeに途中の変更が残る前提。再実行前にworktreeの状態を確認してほしい。
  • 既定値（2時間・30分）が運用に合っているか確認してほしい。
