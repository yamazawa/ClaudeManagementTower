サブタスクリポジトリ切り替え時は前回のIssue一覧をすぐ表示し、画面を止めずに再取得するー①
ブランチissue-207-subtask-1

2. 実装結果

成功

リポジトリ切り替え時、保持しているIssue一覧があればすぐ表示し、画面を止めずに最新の一覧へ差し替えるようにした。

保持が無い初回のみ、従来どおり画面をブロックして「更新中…」を表示する。

4. 自律判断した事項

No.判断理由・前提
1保持キーは通常時「リポジトリID＋状態フィルタ」、MRステータスフィルタ選択中は「matchedIssueKey()（リポジトリID＋対象Issue番号の組）」とした。MRステータスフィルタ選択中は一覧の中身が絞り込み対象の番号で決まるため。
2保持一覧の即時描画もrunSelectionRequest（blocking: false）経由とした。先頭Issueの内容（DB上のMR一覧）の取得が必要なため。後発の要求で上書きしない既存の仕組みをそのまま使える。
3即時描画の後に別リポジトリへ切り替わっていた場合は再取得しない。再取得の要求が後発扱いになり、切り替え先の取得結果を捨ててしまうのを防ぐため。
4配列でない応答（取得失敗時のエラー応答）は保持しない。次回切り替え時に不正な値で描画しないため。
5保持データはメモリ上のみ（ページ再読み込みで消える）とした。Issueの指示が「画面側で保持」のため。localStorage等への永続化は範囲外とした。
6選択中Issueが再取得で消えた場合は、既存のfetchIssueSelectionの再選択処理に任せた。Issueの指示どおり。
